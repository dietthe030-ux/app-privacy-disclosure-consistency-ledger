# Stage 2 — App Privacy Disclosure Consistency Ledger Implementation Specification

One Intelligent Contract. Storage: `records: TreeMap[str, Record]`, `record_ids: DynArray[str]`; `Record` contains owner, app_id, platform, store_url, policy_url, state, verdict, revision. `Assessment` contains revision, checked_at, four normalized category values, retention kind/days, verdict, both source digests and exact sorted decision JSON. Use `@allow_storage @dataclass`; all fields are class-body typed.

API: `create(id, app_id, store_url, policy_url, platform)` any caller, HTTPS/length/host/unique validation, stores DRAFT; `freeze(id)` owner only, DRAFT -> FROZEN; `assess(id)` any caller, FROZEN only, one `gl.eq_principle.strict_eq(fetch_decision)` call, validates exact schema, stores ASSESSED revision 1; `reassess(id)` any caller, ASSESSED only, appends revision; `get(id)`, `get_assessment(id, revision)`, `list_ids()` views. Missing/unknown source fields map to `UNRESOLVED` or `DISCLOSURE_MISSING`; no reasoning text controls state.

Canonical JSON: `{"categories":[...],"policy_digest":"64hex","retention_days":0,"retention_kind":"DAYS|INDEFINITE|UNKNOWN","store_digest":"64hex","verdict":"..."}` with sorted keys and bounded arrays. Frontend screens: list, create, detail; retain tx hash, wait for `FINALIZED`, require `FINISHED_WITH_RETURN`, then read `get` once. Tests: Direct validation/history, Studio stable/missing/conflicting source, Vercel wallet/reload/error/readback. Deploy order: schema probe -> local/Direct -> Studio -> frontend -> Vercel. WRONG/CORRECT: do not compare raw pages or overwrite history; normalize bounded fields and append immutable assessments.
